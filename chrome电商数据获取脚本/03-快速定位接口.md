# 03 · 快速定位接口

目标：在一个已经打开的生意参谋页面旁边，**不新开 tab**，快速找到某个 URL/tab 对应的接口。

## 最快路径（推荐）

### 第 1 步：读已加载的 JS 资源

在**已打开的同域页面**控制台执行：

```js
performance.getEntriesByType('resource')
  .map(e => e.name)
  .filter(n => /\.js(\?|$)/.test(n))
```

会看到类似：

```text
https://g.alicdn.com/dt/op-cc/2.4.238/app.js
https://g.alicdn.com/dt/op-cc/2.4.238/vendors.js
https://g.alicdn.com/dt/op-cc/2.4.238/65.js
https://g.alicdn.com/dt/op-cc/2.4.238/EditTargetLazy.js
https://g.alicdn.com/dt/ops-flow/2.0.185/app.js
```

这一步不需要新开 tab，只是读取当前页面的性能条目。

### 第 2 步：确认 app bundle 与版本

HTML 的 `<meta name="microdata">` 里有版本号：

```text
ctxCcVersion=2.4.238          → op-cc
ctxSFlowVersion=2.0.185       → ops-flow
ctxCustomVersion=2.0.79       → op-eportal/op-college
ctxMcVersion=1.6.169          → op-mc
ctxServiceVersion=1.4.111     → op-service
```

常见映射：

| 路由前缀 | app bundle | 版本字段 |
|---|---|---|
| `/cc/*` | `op-cc` | `ctxCcVersion` |
| `/flow/*` | `ops-flow` | `ctxSFlowVersion` |
| `/portal/*` | `op-eportal` | `ctxCustomVersion` |
| `/mc/*` | `op-mc` | `ctxMcVersion` |
| `/qos/*` | `op-service` | `ctxServiceVersion` |
| `/oneauth/*` | `op-eportal` / 共享 | `ctxCustomVersion` |

> 注意：同一个页面会同时加载多个 bundle。比如商品 360 页面会加载 `op-cc` 和 `ops-flow`，流量接口可能出现在 `op-cc/65.js` 里，而不是 `ops-flow` 里。**以 performance 列表为准**。

### 第 3 步：下载并 grep

```bash
curl -s https://g.alicdn.com/dt/op-cc/2.4.238/65.js -o 65.js
grep -oE '"/[^"]+\.json[^"]*"' 65.js | sort -u
```

Python 版本：

```python
import re, urllib.request

url = "https://g.alicdn.com/dt/op-cc/2.4.238/65.js"
text = urllib.request.urlopen(url, timeout=60).read().decode("utf-8", "replace")

# 所有 .json 路径
paths = sorted(set(re.findall(r'["\'](/[^"\']+?\.json[^"\']*)["\']', text)))
for p in paths:
    print(p)
```

重点搜索：

```python
for kw in ["/cc/item/flow", "/cc/item/sale", "/flow/", "activeKey", "item_archives"]:
    idx = text.find(kw)
    if idx >= 0:
        print(kw, text[max(0, idx-800):idx+800])
```

### 第 4 步：从代码上下文提取参数

找到接口字符串后，打印前后约 900 个字符：

```python
idx = text.find("/cc/item/flow/top/v4.json")
print(text[max(0, idx-900):idx+900])
```

通常能看到：

```js
urls:{main:"today"===t.dateType?"/cc/item/flow/realtime/top/v4.json":"/cc/item/flow/top/v4.json"},
params:{itemId:r,page:1,pageSize:10},
dateType:t.dateType,
dateRange:t.dateRange
```

以及：

```js
trendParams:{device:2,itemId:a,flowBizType:m?"qzt":"classic",...c}
```

从这些上下文可以确定：

- 哪些参数是固定的：`page=1`、`pageSize=10`、`device=2`
- 哪些参数来自页面状态：`dateType`、`dateRange`
- 哪些参数来自行数据：`pageId`、`pPageId`、`pageName`、`flowBizType`
- 哪些参数是枚举：`belong:"all"`

### 第 5 步：取 token，直接调用

`token` 从 HTML 的 meta 里解析：

```python
import re
m = re.search(r'<meta name="microdata" content="([^"]*)"', html)
token = re.search(r'(?:^|;)legalityToken=([^;]*)', m.group(1)).group(1)
```

然后直接 GET：

```text
/cc/item/flow/top/v4.json?itemId=...&page=1&pageSize=10&dateType=day&dateRange=...&_=...&token=...
```

## 如何判断接口属于哪个 tab

看代码里的“更多”链接：

| 接口 | “更多”链接 | 归属 |
|---|---|---|
| `/cc/item/flow/top/v4.json` | `activeKey=flow` | 流量 |
| `/cc/item/searchword/top/v3.json` | `activeKey=flow` | 流量 |
| `/cc/item/sku/top.json` | `activeKey=sale` | 销售 |

规律：

- “更多”链接指向哪个 `activeKey`，这张卡就属于哪个 tab 的数据范围。
- Top10/Top5 通常是**摘要卡**；tab 内的完整表格用另一个接口（如 `/flow/v4/item/source/cc/security.json`）。
- 不要因为接口在同一个 JS bundle 里，就认为它属于同一个 tab。

## 兜底路径：后台 tab 抓包

静态分析找不到接口，或者接口有动态签名时：

```text
1. CDP Target.createTarget({url:"about:blank", background:true})
2. Target.attachToTarget({targetId, flatten:true})
3. Network.enable
4. Page.navigate({url: 目标页面})
5. 收集 Network.requestWillBeSent / responseReceived
6. 等待页面数据加载完（load + 网络空闲）
7. Target.closeTarget
```

注意：

- `background:true` 不抢焦点，但仍是真实页面加载。
- 后台 tab 可能被 Chrome 节流；必要时加启动参数：
  ```text
  --disable-background-timer-throttling
  --disable-backgrounding-occluded-windows
  --disable-renderer-backgrounding
  ```
- 抓到接口后，把 URL 和参数模板保存到 `endpoints.json`，以后不再抓。

## 其他辅助方法

| 方法 | 说明 |
|---|---|
| `localStorage['preFetch-sycm']` | 页面预取缓存，可能含部分接口 URL |
| `performance.getEntriesByType('resource')` | 当前页已加载的 JS/接口资源 |
| 浏览器 HTTP 缓存 | 之前访问过的 bundle 可能在里面，但不易解析 |
| HAR / 抓包记录 | 一次抓包可离线分析，不开浏览器 |
| 浏览器历史/DevTools 面板 | 需要人工操作，不适合全自动 |

## 我们踩过的坑（不要重复）

| 错误做法 | 结果 |
|---|---|
| 只搜 `sycm-micro-v2` | 那里只有壳和路由，没有业务接口 |
| 猜 `sycm-cc/2.4.238/index.js` | 404；实际是 `op-cc/2.4.238/app.js` |
| 猜 `op-cc/2.4.238/index.js` | 404；实际文件是 `app.js` / `vendors.js` / `65.js` |
| 扫 280MB Chrome 缓存找 URL | 缓存索引不是明文，基本找不到 |
| 枚举 151 个 micro-v2 chunk | 只有 11 个存在，且没有业务接口 |
| 先开后台 tab | 多一次真实页面加载；应该先读 performance |

## 正确顺序

```text
1. 已有同域页面？
   ├─ 是 → performance 资源列表 → 下载 app.js/65.js → grep 接口
   └─ 否 → 先读 HTML + meta token，再决定是否需要后台 tab

2. 接口字符串找到了？
   ├─ 是 → 读上下文确定参数 → 直接 GET
   └─ 否 → 后台 tab 抓一次 → 保存模板

3. 参数报 1003？
   → 按 message 补 device / belong / order / pageId 等
```
